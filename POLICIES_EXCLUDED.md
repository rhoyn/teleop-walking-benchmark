# Candidates tried and not included

| candidate | why not |
|---|---|
| `almi` | **Unfeedable.** Dual-policy: `lower.onnx obs[76:93]` is the *output* of a separate 17-action upper-body net driving arm joints a policy may not own, and that net needs a 14-slot end-effector pose command in an undocumented frame. One slot worth 25% RMS never identified. Licence mixed-upstream, no LICENSE file. |
| `asap_pipeline` | **Motion tracker, and a duplicate.** ASAP-lineage tracker blocked on `ref_motion_phase`, a reference-clip phase the waypoint tour has no clip to supply; its other weights are stock Unitree `motion.pt`, already shipped here as `rl_gym`. |
| `bfm` | **Unfetchable.** The single weight file is behind a HuggingFace access gate — 401 on every request without an account — and no licence is declared, so it would be unredistributable even if fetched. |
| `dagger` | **Not a locomotion policy.** A DAgger navigation student over a teacher. Separately blocked on exteroception the harness cannot provide. |
| `dm_g1_agile`, `dm_g1_march` | **Duplicates.** Their ONNX files are byte-identical to `policies/dm_agile/model.onnx` and `policies/dm_march/model.onnx`, both already in the table. Plan-only directories written by a second agent. |
| `from_w1` | **Unfeedable.** 1821-dim observation whose command channel is a reference motion (`v-teleop-extend-vr-max-nolinvel`), not a velocity command. Both G1 checkpoints share it and the project ships no velocity-command fallback. |
| `g1_cu` | **Unfeedable, and unsteerable.** `obs[0:3]` is *world*-frame base linear velocity straight off `qvel` — simulator ground truth a G1 does not publish, and unreconstructable without a global heading. Worse, the command slots are compile-time constants: `obs[96]` has mean +0.8 and variance 0, so the policy cannot be steered at all. |
| `graystars` | **Duplicate.** Its `velocity_v0_exported_policy_raw.onnx` is byte-identical to `policies/rl_mjlab/model.onnx`, already in the table. |
| `huru` | **Implemented, measured, then removed.** Feedable except `obs[0:3]`, pelvis linear velocity, which a G1 does not publish. Briefly run against a simulator velocimeter and measured 0/50 complete, 7.0 s mean survival; removed along with the velocimeter, so the harness again gives a policy only what a G1 publishes. |
| `josabb` | **A different robot.** `g1_with_hands`, 53 joint slots including 12 actuated hand proximals our 29-DoF asset does not have. Also base linear velocity at `obs[0:3]` and a 41-wide action head. Porting it would mean retraining against another asset. |
| `kdh` | **Unfeedable, and non-redistributable.** `base_lin_vel` at `obs[0:3]`, which a G1 does not publish, plus a 37-joint contract covering arms and hands. No LICENSE, and its controller carries an NVIDIA proprietary header explicitly forbidding redistribution. |
| `leggedcontrol` | **Not a G1.** Every checkpoint in the repo targets a Go2 / wheeled platform (`policy_go2w.onnx`). Fails task fit before licensing matters. |
| `loco_mujoco` | **No checkpoint exists.** The project publishes no trained weights at all — not for the G1, not for any of its other 15 robots, on GitHub, HuggingFace or PyPI. There is nothing to port. |
| `mimickit` | **Motion tracker.** The observation carries the reference character's full pose at t+dt, t+2dt and t+3dt, and the tour has no clip to supply. Independently fatal are base height at slot 0 and world-frame base linear velocity at slots 7..9, plus a 29-wide action head driving both arms and both wrists. |
| `motionbricks` | **Not a controller.** A kinematic motion generator: it emits MuJoCo `qpos` frames and never computes a torque — zero `mj_step`, zero `ctrl`, zero actuator across 1515 lines of its demo stack. Its observation also needs a one-hot clip index and a frame index into a clip library. |
| `mturan33` | **Unfetchable.** The named checkpoints sit behind a HuggingFace access gate, 401 on every file. Independently, every locomotion observation in this author's published work opens with base linear velocity, which a G1 does not publish. |
| `pathon` | **Wrong joints, and self-inconsistent.** Ten of its 22 outputs are arm joints and none are waist, and it was trained with the arms frozen for all 5,000 iterations while the tour drives them from a random walk. Its 77-column observation also has no self-consistent reading: the three 22-blocks run `[arm,leg]`, `[leg,arm]`, `[arm,leg]`. |
| `playground` | **Unfeedable.** `mujoco_playground`'s own G1 joystick actor opens with three slots of `noisy_linvel` — pelvis linear velocity read from MJX state, not something a G1 publishes. This is the canonical layout that several other candidates here turn out to be variants of. |
| `polysim` | **Motion tracker, and a duplicate.** ASAP-lineage tracker needing `ref_motion_phase`, and its `dec_loco_model_6600.onnx` is byte-identical to `policies/asap/model.onnx`, already in the table. |
| `protomotions_gtp` | **Motion tracker.** 248 of 342 input scalars — 72% of the observation — are a reference-motion window sampled 20/40/80/160 ms into the future, which the tour has no clip to supply. Its 29 action targets also cover arms and wrists. |
| `rl_hnav` | **Duplicate.** A Nav2/SLAM navigation stack that vendors someone else's walker: both its G1 locomotion checkpoints are byte-identical to `policies/rl_gym/model.pt` and `policies/robomimic/model.pt`. |
| `rsamf_walk` | **Motion tracker.** "walk" names the clip it imitates, not a velocity controller: 152 of 188 observation slots are reference-motion look-ahead frames with absolute pelvis height baked in. Its action normaliser decodes exactly to the 29-DoF joint limits — it drives both shoulders, both elbows and all six wrist DoF. |
| `snow` | **Unfeedable.** A MuJoCo Playground joystick policy: slots 0:3 are `noisy_linvel`, the feedback half of the loop the command in slots 9:12 is compared against — so zeroing them tells a policy commanded to 0.8 m/s that it is standing still. Also 29 actions, and 53 dims of a snow-sensing rig never built. |
| `sunny` | **Unfetchable.** The HuggingFace repo is gated — `"gated":"auto"`, every file 401s — with no card, config, licence or mirror. A genuinely new checkpoint of SB3 lineage, worth revisiting from an account that has accepted the terms. |
| `unity_rl` | **Unfeedable.** All six G1 ONNX read base linear velocity at slots 6..8, and it is deliberately privileged: every other observation is noised, linvel is not. Also Unity left-handed Y-up, joint order recorded nowhere but the scene file, and a low-pass plus double-integrator actuator rather than a position target. |
| `wbc_mjlab` | **Motion tracker.** 39 of 132 observation slots are read out of a motion clip, and the action is a residual on the clip's own pose (`action_mode: reference_residual`) — with no clip there is no `q_ref`, so even the 15 owned entries have no defined meaning. Walking exists here only as a clip to track. |
| `yahmp` | **No checkpoint for the task that would have fitted.** Its three shipped checkpoints are 1727-dim motion trackers. The repo *does* define a velocity-commanded locomotion task that would port cleanly — every privileged term sits in the critic group, never the actor — but no checkpoint for it was ever committed. |
| `yezzzye` | **Too wide.** `base_lin_vel` at `obs[0:3]`, which a G1 does not publish, and a 123-dim observation built over 37 joints including arms and hands, against our 29-DoF asset. MIT-licensed and genuinely trained, so the width is the whole problem; the 37-wide *action* alone would have been fine. |
| `yifeichen` | **Duplicates.** Four repos, 78 weight files hashed. The G1 locomotion ones are byte-identical copies of `policies/robomimic/model.pt` and `policies/rl_gym/model.pt`; the remainder are ASAP motion trackers needing `ref_motion_phase`. |
| `zealot_v26` | **Same training run as a policy already in the table.** Not blocked and not broken — fully feedable, and it could have been ported. It is an earlier rung of the run already shipped as `zealot`: the same repo holds the v28 checkpoint `zealot` uses. A second row would measure the ladder, not a second policy. |
